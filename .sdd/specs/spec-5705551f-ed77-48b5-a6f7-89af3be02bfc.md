# SDD Spec: REQUIRED_BANS Edge Type
**Issue:** [AUT-17] BANNED_AGAINST graph edge is not usefull

## 1. Overview
The current `BANNED_AGAINST` edge type (constant `2`) maps every picked hero to every ban by the opposite team based on normalized frequency. This will be replaced by a new `REQUIRED_BANS` edge type (still type `2`) to better model which bans create favorable conditions for a hero pick. 

A ban of hero $Y$ is "required" for a picked hero $X$ if:
- $Y$ was banned **before** $X$ was picked (by either team).
- OR $Y$ was banned **after** $X$ was picked, AND $Y$ was banned by $X$'s own team.

The new edges will be directed $X \to Y$, and the edge weights will use **win-rate weighting** (wins / total matches), identical to the `SYNERGY` and `ANTAGONIST` edges, replacing the old frequency normalization. 

## 2. Changes to Data Extractor (`src/dota2drafter/embeddings/data_extractor.py`)

### 2.1. Rename Constant and Comments
- Rename `BANNED_AGAINST = 2` to `REQUIRED_BANS = 2`.
- Update docstrings in `build_hero_graph` and `build_pruned_hero_graph` to reflect `- Edge type 2 (REQUIRED_BANS): Directed required-bans edges`.
- Update inline comments that previously stated `(24, 3)` tensor shapes to `(24, 4)` since the `step_index` column is now strictly required.

### 2.2. Harden Tensor Shape Validation
Since `REQUIRED_BANS` relies on temporal step order, the shape of the draft tensors must be strictly validated.
Add a guard at the start of `build_hero_graph` and `build_pruned_hero_graph`:
```python
if x_tensors.shape[-1] < 4:
    raise ValueError("REQUIRED_BANS requires step_index as the 4th column in draft tensors.")
```

### 2.3. Edge Extraction Logic (`build_hero_graph` & `build_pruned_hero_graph`)
- Remove the old `ban_counts` dictionary and replace it with `req_ban_counts: dict[tuple[int, int], list[int]] = {}` to store `[wins, total]`.
- Iterate through each `draft` and extract picks and bans. Keep references to the entire row so `step_index` is accessible.
- For each picked hero $X$ (`is_pick == 1.0`):
  - Read `p_team = int(draft_row[1])`, `p_hero = int(draft_row[2])`, `p_step = int(draft_row[3])`.
  - Calculate team win status: `p_win = radiant_win if p_team == 0 else (1 - radiant_win)`.
  - Iterate through all banned heroes $Y$ (`is_pick == 0.0`):
    - Read `b_team = int(draft_row[1])`, `b_hero = int(draft_row[2])`, `b_step = int(draft_row[3])`.
    - If `b_step < p_step` OR (`b_step > p_step` AND `b_team == p_team`):
      - Update the counts:
        ```python
        if (p_hero, b_hero) not in req_ban_counts:
            req_ban_counts[(p_hero, b_hero)] = [0, 0]
        req_ban_counts[(p_hero, b_hero)][0] += p_win
        req_ban_counts[(p_hero, b_hero)][1] += 1
        ```

### 2.4. Weighting and Pruning Updates
- **In `build_hero_graph`**: Loop over `req_ban_counts`. Filter out noisy edges with `if total < 3: continue`. Calculate `win_rate = wins / total` and append the edge as type `REQUIRED_BANS`.
- **In `build_pruned_hero_graph`**: Calculate `ban_cutoff` using the `total` occurrences from `req_ban_counts.values()` rather than raw counts. Apply the percentile cutoff threshold against the `total`, and append the edge weighted by `win_rate`.
